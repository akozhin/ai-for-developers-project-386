# ADR-003: AI-подбор слота — LangChain-агент с одним инструментом и OpenAI-совместимым провайдером

> **Статус:** Принято · **Дата:** 2026-10-09

## Контекст

Режим «Подобрать с AI» принимает фразу гостя («на следующей неделе в обед по понедельникам») и предлагает до трёх слотов. Бизнес-логика расчёта слотов живёт только в backend; модель не должна бронировать или придумывать время. Провайдер должен меняться конфигом (облако или локальная модель).

## Рассмотренные варианты

1. **Прямой SDK одного провайдера (Anthropic), модель только извлекает параметры** — просто и детерминированно, но привязывает к одному провайдеру, а переход на локальную модель требует переписывания клиента.
2. **Агент без инструмента, слоты передаются модели в промпте** — раздувает промпт данными бронирований и позволяет модели выдумывать слоты.
3. **LangChain-агент с одним инструментом поиска слотов и структурированным ответом поверх OpenAI-совместимого клиента (выбран)** — модель сама уточняет диапазон поиска через инструмент, ответ строго типизирован, провайдер меняется через конфиг.

## Решение

- Агент LangChain (`langchain-openai`, `ChatOpenAI`) с единственным инструментом `search_slots`, который вызывает внутренний метод backend `find_slots` поверх функции слотов (не более 20 слотов за вызов, не более 3 вызовов на запрос). Структурированный ответ: `{ text, slots }`.
- Конфиг: `AI_BASE_URL` (по умолчанию OpenRouter), `AI_API_KEY`, `AI_MODEL` (по умолчанию `anthropic/claude-haiku-4.5`). Для локальной модели достаточно сменить URL и модель; модель должна поддерживать вызов инструментов. `ai_enabled` в профиле равно `true`, когда ключ непуст.
- Слоты в ответе проверяются функцией слотов, не прошедшие проверку отбрасываются. У агента нет инструментов записи: бронирует только гость через форму.
- Защита: текст ≤ 500 символов, лимит 10 запросов в минуту по IP, таймаут 20 секунд, текст гостя не логируется.
- Один запрос — один ответ, без истории диалога. Ввод только текстовый, голоса нет.

## Последствия

- (+) Провайдер меняется конфигом; ответ типизирован; выдуманные слоты не доходят до гостя.
- (+) В тестах модель заменяется заглушкой LangChain, реальная модель в CI не нужна.
- (−) Тяжёлая зависимость (LangChain) ради одного агента с одним инструментом.
- (−) Качество подбора зависит от выбранной модели и её поддержки вызова инструментов.
