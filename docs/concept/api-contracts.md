# API-контракт

> **Источник правды — TypeSpec:** [`api/main.tsp`](../../api/main.tsp). Из него командой `make generate` собираются [`api/openapi.yaml`](../../api/openapi.yaml) (OpenAPI 3.1) и SDK frontend (`frontend/lib/api/generated`). Сгенерированное руками не правится. Решение — [ADR-002](../adr/002-api-contract-typespec.md).
> Этот файл — краткий обзор; при расхождении прав контракт. Подробности (поля, ограничения, примеры) — в `api/openapi.yaml`, Swagger UI — `http://localhost:8000/docs` у запущенного backend.

## Правила изменения

Любое изменение API начинается с `api/main.tsp`: правка контракта → `make generate` → код backend и frontend. `make generate-check` (входит в `make ci`) падает, если сгенерированные файлы не совпадают с закоммиченными. Backend проверяется на соответствие контракту Schemathesis (`backend/tests/test_contract.py`).

## Конвенции

- `application/json`, UTF-8, поля `snake_case`; время — ISO 8601 в UTC (`2026-10-12T08:00:00Z`), даты календаря — `YYYY-MM-DD` по часовому поясу владельца.
- Версия в пути: `/api/v1/...`; `/health` — без версии.
- Авторизации нет: владелец — один заранее заданный профиль, гость записывается без входа.
- Коллекции в обёртке `{ "items": [...] }`; пустая — `200` с `items: []`.
- Создание — `201`, остальное успешное — `200`.

## Эндпоинты

| Метод | Путь | Кто | Назначение |
|-------|------|-----|------------|
| `GET` | `/health` | — | Проверка работоспособности |
| `GET` | `/api/v1/profile` | гость | Имя, часовой пояс, аватар владельца, `ai_enabled` |
| `GET` | `/api/v1/event-types` | гость, владелец | Список типов событий (по возрастанию длительности) |
| `POST` | `/api/v1/event-types` | владелец | Создать тип события (`id` — slug, задаёт владелец) |
| `GET` | `/api/v1/event-types/{id}` | гость | Один тип события |
| `GET` | `/api/v1/event-types/{id}/slots` | гость | Свободные слоты на все 14 дней окна, по дням |
| `POST` | `/api/v1/bookings` | гость | Забронировать слот |
| `GET` | `/api/v1/bookings` | владелец | Предстоящие встречи всех типов по возрастанию начала |
| `POST` | `/api/v1/slot-suggestions` | гость | AI-подбор слотов по фразе (нужен `AI_API_KEY`) |

## Ошибки

Тело любой ошибки — `{ "code": "...", "message": "..." }`; у `422` добавляется `fields: [{ "field", "message" }]`.

| Код | `code` | Когда |
|-----|--------|-------|
| `404` | `event_type_not_found` | Неизвестный или некорректный id типа события |
| `409` | `slot_taken` | Время пересекается с существующим бронированием любого типа (в том числе при гонке запросов) |
| `409` | `slot_not_available` | Время не является слотом: прошлое, ближе запаса до записи, за окном 14 дней, вне рабочих часов, не на сетке 30 минут, не помещается |
| `409` | `event_type_exists` | Тип события с таким `id` уже существует |
| `422` | `validation_error` | Ошибки полей запроса (длины, формат, лишние поля, символ NUL) |
| `429` | `rate_limited` | Превышен лимит запросов к AI (10 в минуту с IP) |
| `503` | `ai_unavailable` | AI не настроен, недоступен или не успел ответить |

Неожиданный сбой сервера отдаёт `500` с `code: "internal_error"` без внутренних подробностей.

## Порядок проверок при бронировании

Поля (`422`) → тип события (`404`) → время (`409`): сначала допустимость времени (`slot_not_available`), затем занятость (`slot_taken`). Окончательный арбитр при одновременных запросах — ограничение PostgreSQL на непересечение интервалов.
